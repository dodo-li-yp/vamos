## 1. 目标用户
- **效率型白领（主力）**：每天在微信、飞书、邮箱、电商之间来回切换，想把重复操作交出去。
- **重度内容用户**：要批量阅读和总结小红书、公众号、B站内容，或者追踪某个博主。
- **求职者和小商家**：需要批量打招呼、比价、处理消息。
- **AI 爱好者和开发者**：自带 API Key，愿意配置无线调试，也想从电脑调用手机。
- 设备要求：只用聊天/网页/文件功能需要 Android 11+；操作 App 需要 Android 12+，推荐 Android 14+。

## 2. 核心场景
1. 「给文件传输助手发一句『明早 9 点开会』」：在后台屏打开微信，找到联系人并发送（发送前需用户确认）。
2. 「这个群今天聊了什么？」：滚动读取群聊记录，输出摘要。
3. 「找个 100 元以内、4.5 星以上的充电器，加入购物车」：只加购，不结算。
4. 「明早 9:40 和 10:00 各定一个闹钟」。
5. 「每天早上 8 点查天气，下雨才提醒我」：定时加条件触发。
6. 双击悬浮胶囊，问「这条消息怎么回比较好？」：把当前屏幕交给 AI。
7. 「打开小红书，把这篇笔记的要点整理给我」：在后台读取内容后总结。
8. 「这个博主最近发了什么？」：逐条阅读帖子并总结。

## 4. P0 强制项详述

### a) 在线更新
**数据源**：腾讯云 COS 广州地域，存储桶名用 `<BUCKET>` 占位，最终名称由运维填写。
- `https://<BUCKET>.cos.ap-guangzhou.myqcloud.com/vamos/version.json`
- `https://<BUCKET>.cos.ap-guangzhou.myqcloud.com/vamos/version.json.sig`（Ed25519 签名，64 字节，Base64 编码）
- APK 放在 `.../vamos/apk/vamos-<versionName>-<versionCode>.apk`
- 全部走 HTTPS。因不上架应用商店，App 内更新**始终开启**，不提供关闭开关。
```json
{
  "versionCode": 5,
  "versionName": "1.2.0",
  "apkUrl": "https://.../vamos-1.2.0-5.apk",
  "sha256": "64位小写hex",
  "size": 41234567,
  "changelog": "· 修复…\n· 新增…",
  "minSupportedVersionCode": 3,
  "force": false
}
```
**检查时机**
- 冷启动后延迟 3 秒在后台检查，同一天最多自动检查 1 次，结果缓存 24 小时。
- 「设置 › 关于 › 检查更新」可以手动检查，不受频率限制。
- 任务执行中不弹更新提示，等任务结束再提示。

**签名校验（第一道关，必须通过）**
1. 下载 `version.json` 的**原始字节**和 `version.json.sig`。
2. 用 **内置在 App 里的 Ed25519 公钥**（编译期常量，不可远程替换）校验签名，签名对象是 `version.json` 的完整原始字节，校验时不能重新序列化。
3. 校验失败，或者 sig 缺失、格式错误：**直接拒绝本次更新**，不解析 JSON、不提示用户，只记日志「更新信息签名无效」；如果是手动检查，提示「更新信息校验失败，请稍后再试」。
4. 私钥离线保存，保管人和方式与 keystore 相同（Dodo 保管，备份存 vault），绝不进源码和 CI 日志。需要轮换时，通过一次发版内置新公钥，并在过渡期同时内置新旧两把公钥。
5. 签名通过后才进入下面的判定规则；APK 下载完成后**仍然**要校验 SHA-256（第二道关）。

**判定规则**
- `remote.versionCode <= 本地 versionCode`：判定为「已是最新」，**拒绝更新**，包括 versionCode 相等的情况。
- `本地 versionCode < minSupportedVersionCode` 或 `force=true`：弹出强制更新弹窗，不可关闭，只能选「更新」或「退出」。
- 其他情况：普通提示，可以「稍后」或「忽略此版本」。
- JSON 字段缺失、格式不合法、apkUrl 不是 https：静默失败，只记日志。

**下载**
- 前台服务加通知栏进度条，App 内也显示进度（百分比、速度、已下载/总大小）。
- 断点续传：用 HTTP Range 请求，临时文件存为 `cacheDir/update/vamos-<vc>.apk.part`，并记录 ETag。服务端不支持 Range 或 ETag 变化时，从头重新下载。
- 默认只在 Wi-Fi 下自动下载；使用移动网络时先弹窗确认，并提示 size。
- 下载前检查剩余空间，不足 size×2 时提示用户清理。
- 网络失败自动重试 3 次（指数退避），之后显示「重试」按钮。

**校验（不通过一律失败）**
1. 文件大小必须等于 `size`。
2. SHA-256 必须等于 `sha256`（忽略大小写），不一致就删除文件并提示「安装包校验失败」，**不允许安装**。
3. 用 PackageManager 解析 APK：包名必须为 `com.yongpeng.vamos`，versionCode 必须大于本地；签名证书必须和当前安装包一致（防止被替换）。上游已有 `ApkIntegrity`，在此基础上沿用并增强。

**安装**
- Android 8+ 检查 `canRequestPackageInstalls()`；没有授权时引导到「安装未知应用」设置页，返回后自动继续安装。
- 首选 `PackageInstaller` Session 覆盖安装，备选方案是 `FileProvider`（`${applicationId}.fileprovider`，路径只开放 `cache/update/`）加 `ACTION_VIEW`。
- 签名相同、versionCode 更高时由系统覆盖安装，数据保留。

**失败与回滚**
| 情况 | 处理 |
|---|---|
| 下载中断 | 保留 .part 文件，下次续传 |
| 校验失败 | 删除文件，上报原因，不重试同一个文件超过 2 次 |
| 用户取消安装 | 保留已校验的 APK，7 天内再次点「安装」直接使用 |
| 系统报签名冲突或降级 | 提示「安装包异常」，不引导用户卸载，并记录日志 |
| 新版本启动崩溃 | Android 不支持自动降级。服务端回滚做法：撤下坏版本，发布 **更高 versionCode** 的修复包（内容可以等同于上一稳定版） |
| COS 不可用 | 静默失败，手动检查时提示「暂时无法检查更新」 |
| version.json 签名校验失败 | 拒绝更新，不下载 APK，记录日志（可能是被篡改或劫持） |

**清理**：安装成功后在下次启动时删除 `cache/update/` 下的全部文件；超过 7 天未安装的 APK 和 .part 文件也一并清理。

### b) 签名与版本
- **固定 release keystore**：所有正式包用同一个 keystore 签名。**由 Dodo 保管，备份存放在 vault**，绝不放进源码包，**严禁提交到 Git**；`.gitignore` 排除 `*.jks/*.keystore/keystore.properties`。签名参数通过本地 `keystore.properties` 或 CI Secret 注入。keystore 一旦丢失，所有用户都无法覆盖升级，所以要列为最高等级资产。
- **versionCode**：正整数，每次发布严格递增，不复用、不回退。
- **versionName**：遵循 SemVer `MAJOR.MINOR.PATCH`（如 1.2.0），预发布版写作 `1.3.0-beta.1`。
- App 端拒绝 versionCode 不大于本地的更新（§4a），系统层面的覆盖安装也会拒绝降级。
- **发布清单（每次发布逐项勾选）**
  1. versionCode +1，versionName 按 SemVer 更新，CHANGES.md 和 changelog 已写。
  2. 用 release keystore 签名，执行 `apksigner verify --print-certs`，确认证书指纹和基线一致。
  3. 计算 `sha256sum`，记录文件 size。
  4. 先上传 APK 到 COS 广州桶（文件名带版本号，不覆盖旧文件）。
  5. 用 Ed25519 私钥对最终版 version.json 签名，生成 `.sig`，并在本地用公钥验一次；先上传 `.sig`，**最后**上传 version.json（两个文件要在同一批次内完成）。
  6. 在旧版本真机上走一遍完整升级流程（普通更新和强制更新各一次）。
  7. 确认 LICENSE / NOTICE / 开源许可页齐全，且 UI 里没有出现 "Mika" 字样（用 grep 检查）。
  8. 打 Git tag `v<versionName>`，保留 mapping 文件。

## 5. 安全与权限

**权限清单**（上游 Manifest 已有，Vamos 沿用；用途说明要在 UI 里展示）
| 权限 | 用途 |
|---|---|
| INTERNET / ACCESS_NETWORK_STATE | 调用模型 API、检查更新 |
| BIND_ACCESSIBILITY_SERVICE（无障碍服务） | 读取界面、执行操作（具体作用范围以 §10 第 10 项的 Spike 结论为准） |
| WRITE_SECURE_SETTINGS（经无线调试授予） | 自动重新打开无线调试等 |
| 无线调试配对（shell 身份 helper） | 创建后台虚拟屏并注入操作 |
| FOREGROUND_SERVICE（SPECIAL_USE / DATA_SYNC） | 任务执行、下载更新 |
| POST_NOTIFICATIONS | 进度和停止按钮 |
| RECORD_AUDIO | 语音输入 |
| REQUEST_INSTALL_PACKAGES | 在线更新 |
| SCHEDULE_EXACT_ALARM / SET_ALARM / RECEIVE_BOOT_COMPLETED / WAKE_LOCK | 定时任务、设置闹钟 |
| READ_MEDIA_IMAGES / READ_MEDIA_VISUAL_USER_SELECTED / READ_EXTERNAL_STORAGE | 附件 |
原则：按需申请，每个权限先在 App 内说明用途；拒绝后对应功能降级，不阻断其余功能。

**敏感操作确认（P0）**
- 必须确认：支付或下单、发送消息/邮件/评论、删除（文件、聊天、联系人等）、修改账号或系统设置、对外发布内容。
- 确认卡片展示：目标 App、对象（收件人或金额）、即将执行的动作，以及屏幕截图。
- 用户 60 秒内没有响应，视为拒绝，任务暂停。
- 「自主模式」也不能跳过支付确认（锁定），其他类别可由用户自己选择。
- 登录、验证码、支付密码一律交给用户本人输入（沿用上游行为），AI 不代填。

**密钥存储**：API Key、OAuth token 用 `EncryptedSharedPreferences`（AES256-GCM，MasterKey 存在 Android Keystore 中）。不写日志，不进备份（`allowBackup` 排除），界面上只显示后 4 位。

**停止开关（Kill switch）**：通知栏常驻「停止」、悬浮胶囊长按停止、App 内醒目的停止按钮。停止后 1 秒内中断所有注入操作并释放虚拟屏；设置里还有「一键关闭手机控制」，会断开 helper 连接。

**隐私**：Vamos 不设自有服务器，对话只发给用户配置的模型厂商。更新检查只访问 COS，不携带任何用户数据。

| 定时任务 | 管理定时和条件任务 | 列表、开关、下次运行时间 |
| 记忆与技能 | 查看和删除 | 列表、编辑、删除 |
| 兼容性自检 | 设备检测 | 12 项结果、导出 |

| 更新弹窗 | 在线更新 | changelog、大小、进度条、更新/稍后/退出（强制更新时） |

## 8. UI 规范要点
**风格**：沿用团队的 **新中式 + 液态玻璃** 风格，加一个「AI 执行态」强调色（青碧），用来区分「AI 正在操作」和「需要你确认」（朱砂）。
| Token | 日间 | 夜间 | 用途 |
|---|---|---|---|
| `bg/paper` 宣纸白 | #F4F1E8 | #1A1C1B | 背景 |
| `text/ink` 淡墨 | #3A3A36 | #E6E2D6 | 主文字 |
| `text/ink-2` | #6E6C64 | #A3A096 | 次文字 |
| `brand/dai` 黛青 | #5B7A72 | #7FA097 | 主色、按钮 |
| `agent/qingbi` 青碧 | #3F8F86 | #5FB3A8 | AI 执行中、进度、后台屏边框 |
| `accent/cinnabar` 朱砂 | #B5473A | #D0645A | 敏感确认、停止、错误 |
| `state/amber` 琥珀 | #C48A3A | #D9A55A | 警告 |
| `glass/fill` | 白 28%（常态）/ 42%（浮层） | 白 8% / 14% | 玻璃面板 |
| `glass/stroke` | 白 50%，0.5dp | 白 12% | 描边 |
模糊：blur 24dp（Android 12+ 用 RenderEffect，低版本退化为不透明 92%）。

**字号**（sp）：Display 28/36、Title 20/28、Subtitle 16/24 Medium、Body 15/22、Caption 12/16、Mono 13（日志）。中文用系统字体，标题可选思源宋体，体现新中式风格。
**圆角**：卡片 20dp，弹层/底部面板 28dp，按钮 14dp（胶囊按钮用全圆角），输入框 16dp，悬浮胶囊全圆角。
**间距**：8dp 网格（4 只用于微调），页边距 16dp，卡片内边距 16dp，模块间距 24dp，触控热区 ≥ 48dp。
**组件命名**：`Vm` 前缀加 PascalCase，例如 `VmGlassCard`、`VmPrimaryButton`、`VmStopButton`、`VmConfirmSheet`、`VmTaskTimeline`、`VmCapsule`、`VmUpdateDialog`。颜色 token 用 `VmColors.agentQingbi` 形式。动效：任务执行中，后台屏小窗的青碧描边做呼吸动画，周期 1.6 秒。

## 10. 已决策（2026-11-01）
| # | 问题 | 决策 | 理由 / 决策人 |
|---|---|---|---|
| 1 | 更新托管 | 腾讯云 COS 广州（ap-guangzhou），存储桶名用 `<BUCKET>` 占位；version.json 必须通过 Ed25519 验签（公钥内置），验签失败就拒绝，之后仍校验 APK 的 SHA-256 | 老板决策；防止 CDN 或中间人篡改更新信息 |
| 2 | 应用商店 | 暂不上架，App 内更新始终开启 | 老板决策 |
| 3 | 签名密钥 | keystore 由 Dodo 保管，备份存放在 vault，绝不进源码包；Ed25519 私钥同样处理 | 老板决策；两把密钥同级管理，减少遗失风险 |
| 4 | Linux 沙箱 | V1 整体移除（PRoot/talloc/Alpine），放进不做清单 | 老板决策；消除 GPL/LGPL 义务，同时缩小 APK |
| 5 | 默认模型 | 首次启动默认推荐 DeepSeek；ChatGPT / xAI / OpenRouter 等登录方式全部保留 | 老板决策 |
| 6 | 自主模式下的确认 | 支付/下单始终需要确认（锁定）；删除、发消息等其他类别默认开启确认，用户可以逐项关闭；关闭时二次提示风险 | 推荐方案：资金损失不可逆，其余操作交给用户选择，兼顾效率 |
| 7 | 对外说明基于开源项目 | 不在营销中主动宣传，只在「关于 › 开源许可」中如实保留署名；被问到时如实回答 | 推荐方案：满足 Apache-2.0，也遵守「不对外出现 Mika」的要求 |
| 8 | 法律文档 | V1 发布前上线隐私政策、用户协议和免责声明三份文档，由产品起草、法务审核；首次启动必须勾选同意 | 推荐方案：自动操作第三方 App 有违反对方条款的风险，需要明确免责 |
| 9 | CLI/MCP 是否进 V1 | 不进 V1：代码保留、入口隐藏，V1.1 品牌化后开放 | 推荐方案：V1 聚焦手机端，减少对外暴露面和品牌残留 |
| 10 | 无障碍服务与 shell helper 的职责 | 列为 V1 第 1 周研发 Spike：读代码出书面结论（谁负责截图、读控件树、注入操作），据此定稿权限说明文案；如果无障碍服务不是必需，就降级为可选 | 推荐方案：权限说明必须真实，涉及上架和隐私合规 |
| 11 | 签名公钥轮换 | 预留双公钥机制，V1 只内置 1 把 | 推荐方案：成本低，避免将来私钥泄露时无法补救 |
| 12 | 崩溃上报 | V1 不做 | 推荐方案：遵守「无自有服务器」的隐私承诺 |

## 11. 给 UI 设计师
**需要设计的页面**：欢迎/引导、法律条款同意、模型设置（DeepSeek 置顶推荐）、手机控制配对向导、对话首页（含示例任务卡）、会话抽屉、任务执行（时间线 + 后台屏小窗）、敏感确认弹层、浏览器、定时任务、记忆与技能、兼容性自检、设置总页、关于/开源许可、更新弹窗，以及悬浮胶囊（展开/收起）。每个页面都要出日间和夜间两套。

**关键状态（必须逐一出图）**
| 场景 | 状态 |
|---|---|
| 引导 / 无线调试配对向导 | 6 步清单中的：未开始 / 当前步骤高亮 / 自动打勾完成 / 检测不到时显示「我已开启」 / 配对码输入 / 连接中 / 连接成功 / 失败重试 / 跳过 |
| 任务执行 | 思考中 / 操作中（青碧呼吸描边 + 后台屏小窗）/ 等待用户接管（登录、验证码）/ 已停止（汇报进度 + 「继续」）/ 完成 / 失败。**停止按钮始终可见**，用朱砂色，热区 ≥ 48dp；通知栏也要有停止按钮 |
| 确认弹层 | 支付（锁定必确认）/ 发消息 / 删除 / 修改设置四种样式；包含动作摘要、对象、截图、允许和拒绝按钮、60 秒倒计时、超时后的状态 |
| 更新 | 有新版本（普通，可稍后/忽略）/ 强制更新（不可关闭）/ 移动网络确认 / 下载中（进度、速度、暂停后续传）/ 校验中 / **校验失败**（签名或 SHA-256 不通过，朱砂色提示 + 重试）/ 需要授权「安装未知应用」/ 安装中 / 已是最新 / 检查失败 |
| 通用 | 空状态、加载中、断网、未配置模型、未配对手机控制 |

**UI 规则**：严格使用 §8 定义的 token，不要自造颜色。青碧只用于「AI 正在执行」，朱砂只用于确认、停止和错误；8dp 网格；组件统一用 `Vm` 前缀命名；玻璃效果为 blur 24dp + 白 28%/42%（Android 11 退化为不透明面板）。**UI 中不得出现 "Mika"**，只用 Vamos 品牌；文字对比度 ≥ 4.5:1，深色模式同样要满足。
